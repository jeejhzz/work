# 채용현황 관리체계

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 |
| 최종 수정일 | 2026-07-13 |
| 담당 역할 | 인사팀 채용 담당자 |
| 수행 주기 | 주 1회 점검, 월 1회 요약 보고 |

## 1. 업무 개요

채용 공고가 여러 그룹(SoC·AI·Core·제품개발·사업개발 등)에 흩어져 있으면, 어떤 포지션이 얼마나 오래 열려 있는지, 어디서 막혀 있는지 파악하기 어렵습니다. 채용 사이트(그리팅 등)는 공고 게시와 지원자 개별 관리는 잘 되지만, **회사 전체 채용 현황을 한 화면에서** 보여주지는 않습니다. 이 문서는 그 빈틈을 메우는 관리 체계입니다.

## 2. 관리 항목 (포지션별로 추적하는 정보)

- 직무명 / 소속 그룹
- 신입·경력 구분
- 채용 인원
- **진행 상태** — 모집중 → 서류전형 → 면접전형 → 처우협의 → 최종합격, 또는 채용마감
- 담당 채용담당자
- 공고 마감일 (상시채용 여부 포함)
- 메모 (특이사항, 정체 사유 등)

## 3. 운영 주기

1. **주 1회** 채용 현황 점검 — 각 담당자가 대시보드에서 담당 포지션의 진행 상태를 갱신
2. 상태가 **2주 이상 그대로**면 정체된 것으로 보고 원인 확인 (서류 저조/면접 일정 지연 등)
3. **월 1회** 그룹별 오픈 포지션 수, 채용 완료 수를 경영진에게 요약 보고

## 4. 도구 역할 분담

| 도구 | 역할 |
|---|---|
| 채용 현황 대시보드 (`HR-업무매뉴얼.html` 내장) | 전체 그림을 한눈에 보는 용도. 상태·담당자·마감일만 빠르게 갱신 |
| 그리팅(채용 사이트) | 공고 게시, 개별 지원자 서류·이력 관리 |

## 6. 자주 발생하는 이슈와 대처

| 상황 | 대처 방법 |
|---|---|
| 공고는 열려 있는데 실제로는 중단된 경우 | 상태를 "채용마감"으로 바꿔 대시보드와 실제 상황이 어긋나지 않게 함 |
| 상시채용 공고는 얼마나 오래 열려 있었는지 놓치기 쉬움 | 메모란에 게시일을 함께 기록해두는 것을 권장 |
